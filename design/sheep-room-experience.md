## 体验顺序

1. 进入可渲染的低多边形房间全景，保留博客品牌。房间里有复古电脑、桌椅、门、绿植和墙上购物袋黑板；底部提供开始和视角切换。
2. 开始前弹出目标面板：客厅、卧室、书房、餐厅；「说说你的布置想法」合并风格与用途，右侧上方为人民币总预算，下方为购物时间（默认 2.5 分钟，可填 0.5–10 分钟）；左侧想法框与右侧两项整体对齐，手机端两项并排。移除左下角说明。想法原文完整传给 Agent 和后续生图。关闭面板可继续看房间。确认之前不启动 Agent 或计时。
3. 确认后收起面板，镜头约 1.5 秒从全景连续推近至电脑正面。完成镜头移动后启动逛店。电脑网页是画面主体，黑板在旁；不再有大段进度文案挡住场景。
4. Agent 在真实宜家中国站搜索、点击、滚动、打开详情，再明确决定加入小屋购物袋。鼠标沿实际执行坐标移动；连续网页画面不等待模型回复。等待决策时只显示短状态。
5. 加入时显示商品照片、名字和人民币价格的小提示；黑板同步商品、数量、小计。点开商品不等于购买意向；只收到已验证的加入事件才增加数量。
6. 结束后展示商品图册，可逐个查看图片、规格、价格、选中理由和原商品页。完整清单展示所有商品、数量、单价和总额，可复制保存。
7. 用户在完整清单后触发一次生图：传入同一份服务端清单及商品参考图片。效果图保留下载和返回清单入口。

桌面先验收。手机也保持同样的步骤，近景优先看清屏幕，购物袋用可展开面板，不能把整张桌面画面缩成邮票或用大段说明占满屏幕。

## 调研结论与证据

- 本地代码原来每个模型动作后才 screenshot；操作期间没有画面，鼠标没有可见轨迹。模型速度和浏览器画面刷新必须分开。
- Chrome CDP 的 Page.startScreencast / screencastFrame / screencastFrameAck 可持续传画面；Playwright 已经能创建 CDPSession，不增加浏览器服务或 Python 运行时。
- Steel Browser 的 casting.handler.ts 使用 CDP 画面事件并确认帧；借鉴「独立传画面、会话结束释放资源」这一机制，不引入其整套服务。
- Browser-use 的 default_action_watchdog.py 从元素几何位置执行真实鼠标移动、按下和松开。借鉴「定位后执行并验证结果」，不复制其代码；前端装饰鼠标不能凭空表演点击。
- Three.js CanvasTexture 可以更新电脑屏幕；相机移动由明确视角与过渡时长控制，不用每帧固定 lerp 系数决定不稳定的动画时间。
- 本地 `node scripts/room-stream-check.mjs` 已通过：1180×760 测试网页，约 1.58 秒收到 86 帧，12 次真实 mousemove，点击坐标与页面事件一致。是本地能力验证，不是宜家端到端成功，也不是线上帧率保证。模型调用为零。
- 宜家中国站实测：主页搜索需要打开浮层中的实际搜索输入；只填写顶部输入并回车可能不跳转。BILLY 商品页能读取照片、货号 005.220.47、白色、80×28×202 厘米及 ¥399 参考价。加入购物袋→确认规格后跳到登录页。用户因此选择小屋自有购物袋；不登录、不模拟商家加购成功。
- 视频画面是美国站、美元，与中国站的 DOM、货号和购物流程不同。没有原作者源码，不能认定其实际采用 Three.js、某个直播协议或某种生图 API；这里记录的是经过核实的复现方案。
- OpenAI 官方 Images API 支持参考图片编辑路径；第三方 AICode007 是否完整兼容该路径仍需最终验证。模型列表可用不等于图片接口已成功，不用纯文字生图悄悄替代参考图输入。

## 数据流与实现

```text
房间目标 → 本地服务 → Luna（网页文字）→ Playwright / 宜家网页
                          ↑                   │
                          └── 下一次页面状态 ──┘
                                              │
                      ┌── CDP 画面 → SSE → 3D 电脑屏幕
                      └── 明确加入 → 服务端购物袋 → 黑板 / 图册 / 清单
                                                │
                                      清单 + 商品图片 → 最后一次生图
```

最小路径是保留现有 Three.js、Playwright、Node、SSE，重写小屋编排。新增运行依赖、生产后台服务、用户配置均为零。涉及 10 个代码/检查文件，另更新设计与使用说明；这是体验和数据流重做，不是一次 CSS 微调。暂不扩展源氏木语、不做账号购物、支付或排行榜。

- `SheepRoomPage.tsx`：全景 / 目标面板 / 推近 / 逛店 / 图册 / 清单 / 生图状态。目标面板用原生 dialog 管理焦点。模型等待不触发换场景。
- `SheepRoomScene.tsx`：全景和正面近景；连续屏幕贴图；黑板贴图；镜头结束通知。保留真实 Three.js 场景。
- 小屋专用 CSS：舞台布局、移动端视角、浅色胶囊、图册与收据。
- `server-room-browser.mjs`：可见控件与搜索浮层、真实移动鼠标、CDP 连续帧、显式 add 动作；商品必须有来源、价格和图片；禁止商家登录/支付。
- `server.mjs`：SSE 区分 frame / step / bag / session / done / error。网络积压时丢旧视频帧，购物袋事件不能丢。
- `server-room.mjs`：保存本轮已核实清单；最终生图用 runId 取服务端记录，不信任前端重传任意商品。调用图片编辑接口传商品图及完整数量与规格。每轮只发一次生图请求，结果不确定时不自动重试扣费。

商品字段：id、name、description、sku、image、quantity、price、currency=CNY、url、reason、checkedAt。当前按规范商品 URL 去重；SKU 是有则保留的补充字段。金额按分计算；计时和已加入件数不混淆。

## 验证与失败处理

- 本地连续帧探针、商品提取/预算/URL 校验脚本、类型构建和变更文件 lint。
- 使用明确标注的本地测试数据验证从全景、目标、近景、添加商品、图册到完整清单，不把测试回放展示为真实 Agent。
- 真站冒烟验证搜索浮层、商品图片与显式收录；不会在调试阶段生成多张效果图。
- 页面未加载完、图片缺失、价格未识别时不计入袋子；说明具体步骤失败，已有袋子保留。
- 取消或网络中断时停止浏览器工作，已有结果可查看，标注本轮未完整结束。
- 网页直播与模型决策分离；限制画面发送频率、及时 ack，不在 React 中保留历史 base64 帧。
- 视角切换不重启 Agent；镜头结束之前不开始浏览；快速重复点击只能创建一轮。
- 只有完成清单才能触发生图；重复点击、失败重试、客户端篡改不能重复计费或改变服务端商品。
- 生产生图兼容性、真站响应时间、移动端实机流畅度仍需实测，不能从本地探针推断。
- 本轮只本地开发验证，无数据迁移，无商家账号状态；回退代码不会改变真实购物车。不提交、推送或部署。
