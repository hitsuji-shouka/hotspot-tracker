网站写完了，跑在 `localhost:7100` 上。但只有自己能看到的网站不算网站——这篇记录它从本地走向 `hitsuji-shouka.com` 的完整过程：域名、Cloudflare、以及一条 push 即部署的流水线。

## 先解决「别人怎么访问」

最开始的需求很简单：手机也要能看。最省事的方案是 Cloudflare 的临时隧道，一条命令把本地端口暴露成一个 `*.trycloudflare.com` 的公网地址，手机上立刻就能打开。

但临时域名每次重启都会变，只能用来预览，不能当门面。于是正式方案定为：**云服务器（阿里云 ECS）跑静态站点 + 自己的域名 + 自动部署**。

## 域名：实名审核与备案的岔路口

买下 `hitsuji-shouka.com` 之后，先等域名实名审核通过。接着遇到一个所有国内站长都会面对的岔路口：

- **域名直接解析到国内服务器**：需要 ICP 备案，周期一到三周，期间网站不能开；
- **域名托管在 Cloudflare，走 Tunnel 回源**：流量从 Cloudflare 的边缘节点进隧道，域名不直接指向国内 IP，不需要备案，还白拿 HTTPS 和 CDN。

我选了后者。不是因为备案不好，而是想先让网站跑起来，备案可以之后再补。

## Cloudflare Tunnel 配置过程

整个过程在 Cloudflare Zero Trust 控制台完成，核心四步：

1. **把域名的 NS 记录改到 Cloudflare**——在域名注册商那里把 DNS 服务器换成 Cloudflare 分配的两个地址，然后等生效（这一步只能等，通常几分钟到几小时）；
2. **创建 Tunnel**——Networks → Tunnels，选 Cloudflared，拿到一串安装命令；
3. **在服务器上运行 cloudflared**——命令会完成授权并把隧道注册为系统服务，开机自启；
4. **绑定公网域名**——给 Tunnel 配一个 Public Hostname，比如 `hitsuji-shouka.com` 指回服务器的 `localhost:80`。

配完之后，浏览器输入域名，HTTPS 是 Cloudflare 自动签发的，证书的活儿全省了。

## 一条 push 即部署的流水线

手动传文件部署迟早会烦，所以用 GitHub Actions 把部署自动化了：

```
本地改代码 → git push → GitHub Actions 自动构建 → rsync 到 ECS → 上线
```

要点是构建产物里的静态资源（JS/CSS）换了新文件名就上线，但服务器上的 `dist/data` 榜单数据和收藏同步数据不能被覆盖——rsync 时要排除掉。

这套流程带来的最大改变是心态：**改网站变成了一件没有负担的事**。调一行文案、换一张封面，push 完喝口水，线上就是新的了。

## 踩过的坑

- **favicon 是浏览器缓存最顽固的东西**。换了图标标签页死活不变，最后靠给链接加 `?v=3` 参数强制刷新才生效；
- **单页应用的深路径 404**。构建时 base 路径配置不对，直接访问 `/shelf` 这种子路径会白屏——检查线上时一定要直接访问深链接，不能只看首页；
- **「截图验证」比「构建成功」重要**。有一次构建全绿，但深色主题下 Tab 文字直接隐形。从那以后每次改完都用无头浏览器截一张图亲眼确认。

## 最后

现在打开 [hitsuji-shouka.com](https://hitsuji-shouka.com)，首页是简历，「漫游」里是书影音，「博客」里就是这篇文章。从一句话需求到一个有固定域名的个人网站，中间隔的其实不是技术，而是把每一步都真正做完。
